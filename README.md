# autodesk-blocker

Windows batch scripts that block network access for executables inside a
given folder (and all of its subfolders, including hidden ones) using the
built-in Windows Firewall. Useful for cutting off an application's
phone-home/licensing traffic without blocking your whole internet
connection.

The scripts don't hardcode anything Autodesk-specific — point `block.bat`
at any install directory and it will block every `.exe` it finds under it.

## Scripts

### `find_features.py`
This will take multiple License.lic or lic.dat files and combine all the features as a set (no dupes) and write it to features.txt 
```
# Example: lic1.dat, lic2.dat, etc in lics/ directory you'd have to create
python3 find_features.py lics/
```

### `discover.bat`
Read-only scan for known Autodesk install/data locations: `Program Files`,
`Program Files (x86)`, `ProgramData`, and every user profile's `AppData`
(Roaming + Local). Prints each match plus a recursive `.exe` count, and
writes the plain list of matched directories (one per line) to
`block-list.txt`, which `block-list.bat` reads. Makes no other changes to
the system.

- Self-elevates (needed to read other users' `AppData` folders).
- Usage:
  ```bat
  discover.bat
  ```
- Backed by `discover.ps1`, which must sit next to it.
- Re-running it **overwrites** `block-list.txt` — move any manually-added
  lines elsewhere first if you want to keep them.

### `block.bat`
Blocks all inbound and outbound traffic for every `.exe` found recursively
under a given directory (hidden files and hidden folders are included).

- Self-elevates: if not run as Administrator, it relaunches itself with a
  UAC prompt.
- Usage:
  ```bat
  block.bat "C:\Path\To\Folder"
  ```
  You can also drag a folder onto `block.bat`, or just double-click it and
  type/paste the path when prompted.
- For every `.exe` found, it adds one inbound and one outbound block rule
  (`AutodeskBlocker_In` / `AutodeskBlocker_Out`) scoped to that program's
  full path, for all firewall profiles.

### `block-list.bat`
Wrapper around `block.bat` for blocking several directories in one go.
Reads directory paths (one per line) from `block-list.txt`, next to this
script, and calls `block.bat` for each. Elevates once up front so
`block.bat` doesn't prompt for UAC on every line.

- `block-list.txt` is generated by `discover.bat`, or you can create/edit
  it by hand — one directory path per line, no quotes needed. Blank lines
  and lines starting with `#` are ignored.
- Usage:
  ```bat
  block-list.bat
  ```

### `unblock.bat`
Removes every firewall rule created by `block.bat` (matched by rule name),
restoring normal network access.

- Also self-elevates if needed.
- Usage:
  ```bat
  unblock.bat
  ```

### `status.bat`
Lists the firewall rules currently created by `block.bat`: direction,
action, enabled state, and the blocked program's path.

- Read-only; usually doesn't require elevation (some systems may still
  restrict rule visibility to Administrators).
- Usage:
  ```bat
  status.bat
  ```

## Known Autodesk locations

Exact folder names are product/year-specific and change annually, so
`discover.bat` scans for them at runtime rather than hardcoding a list.
Typical roots:

- `C:\Program Files\Autodesk\` — product installs (AutoCAD, Revit, 3ds Max,
  Maya, Inventor, Civil 3D, Navisworks, Vault, etc.), one folder per
  product+year.
- `C:\Program Files\Common Files\Autodesk Shared\`
- `C:\Program Files (x86)\Autodesk\` — licensing/identity/update services:
  `AdskLicensing`, `AdskIdentityManager`, `Autodesk Access`,
  `Autodesk Genuine Service`, `Autodesk Desktop App`.
- `C:\ProgramData\Autodesk\` — machine-wide licensing/entitlement cache
  (`CLM`, `Adlm`/`ADSKFlexnetServer`), shared Desktop App data.
- `C:\ProgramData\FLEXnet\` — FlexLM license files (older network-license
  products).
- `%APPDATA%\Autodesk\` (per user) — UI customization, per-product settings.
- `%LOCALAPPDATA%\Autodesk\` (per user) — caches/logs, and **Fusion 360**,
  which is click-to-run and lives entirely under
  `%LOCALAPPDATA%\Autodesk\webdeploy\production\<hash>\` (never under
  Program Files).

Every Windows user profile has its own `AppData` copies, which is why
`discover.bat` walks `C:\Users\*` rather than just the current user.

## Notes

- Requires Windows with `netsh` and PowerShell available (both are
  built-in on modern Windows).
- Rules are identified by name (`AutodeskBlocker_In` / `AutodeskBlocker_Out`),
  so `unblock.bat` doesn't need the original directory to clean up — it
  removes every rule these scripts created, regardless of which `block.bat`
  run created them.
- Re-running `block.bat` on the same or an overlapping directory will add
  duplicate rules for the same program; run `unblock.bat` first if you want
  a clean slate.
- Blocking is per-executable-path. If an application updates and its `.exe`
  moves or is replaced at a different path, re-run `block.bat` to cover the
  new file.
